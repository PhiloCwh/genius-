# genius


在智能合约钱包中会带来：
- 授权流程复杂
- Gas 成本上升
- 行为路径不自然
- 部分 DEX 兼容性差

---

### 核心特性
- 集成 **Permit2**
- 无需传统 approve
- 保留貔貅（只买）属性

### 设计目的

Permit2 允许：
- 合约直接完成授权与调用
- 交易路径更加简洁
- 行为更接近真实用户

> GeniusToken3 是为 **合约钱包刷分场景量身定制的 Token**。

---

### 在刷分中的优势
- 适配智能合约账户
- 交易路径自然
- Gas 更低
- 不易被识别为异常合约行为

### 适用场景
- 合约钱包体系
- 自动化刷分合约
- 长期、稳定刷量系统

---

## GeniusToken4 —— 收税 Token（行为真实性增强）

### 核心特性
- 买卖均可收税
- 税率可配置
- 税收流向可控（回池 / 回地址）

### 设计原因

**完全 0 成本、0 摩擦的交易行为，在大规模情况下并不真实。**

真实市场一定存在：
- 税损
- 滑点
- 摩擦成本

GeniusToken4 的目标是：

> **让刷分行为在链上“看起来更像真的”。**

---

### 在刷分中的优势
- 交易数据更自然
- 提高对反作弊模型的抗性
- 税收仍然在 Genius 体系内回流

### 适用场景
- 长周期刷分
- 高风控项目
- 强反作弊机制的积分系统

---

## 设计总结

| Token | 定位 | 解决的问题 |
|----|----|----|
| Token1 | 权限控制 | 外部地址干扰 |
| Token2 | 单向买入 | 卖出风控信号 |
| Token3 | 合约适配 | 智能钱包交互异常 |
| Token4 | 行为塑形 | 数据过于“完美” |

---

## 设计哲学

Genius 并不追求：

- 刷得最快
- 量做得最大
- 暴力堆交易次数

Genius 追求的是：

> **在协议规则允许范围内，构造最合理的链上行为。**

这些 Token 不是为了投机，  
而是为了 **工程化地模拟真实市场行为**。
