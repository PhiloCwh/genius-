# Genius Token Suite  
### 用于刷分与交易量构造的模块化 Token 体系

> **Token 不是资产，而是工具。**

Genius Token Suite 是一组为 **交易量刷分、链上行为构造、风控规避** 专门设计的 Token 合集，适用于基于 AMM 机制的去中心化交易所（DEX）。

在传统刷量模型中，手续费是不可避免的成本；  
而 Genius 的目标是：**在协议规则允许的前提下，将成本内化，甚至归零。**

---

## 背景说明

在绝大多数 AMM DEX 中：

- 每一笔 Swap 都会产生手续费（通常为 0.01%–0.3%）
- 手续费分配给 LP（流动性提供者）
- 普通用户刷交易量，本质是向 LP 支付成本

**Genius 的核心逻辑是：**

> 如果手续费一定会给 LP，  
> 那么只要 LP 是自己，手续费就不会构成真实成本。

为适配不同刷分阶段、不同风控强度、不同钱包结构，  
Genius 设计了 **四种功能明确、职责单一的 Token 类型**。

---

## Token 总览

| Token | 名称 | 主要作用 |
|----|----|----|
| GeniusToken1 | 黑名单 Token | 控制参与地址 |
| GeniusToken2 | 貔貅 Token | 构造只买行为 |
| GeniusToken3 | Permit2 貔貅 Token | 智能合约钱包适配 |
| GeniusToken4 | 收税 Token | 行为真实性塑形 |

---

## GeniusToken1 —— 黑名单 Token（访问控制型）

### 核心特性
- 支持黑名单（Blacklist）机制
- 可限制特定地址的转账 / 交易行为
- 合约层强控制

### 设计原因

刷分过程中最大的风险之一是 **非预期地址介入**，例如：

- 外部机器人
- 套利地址
- 非授权用户参与交易

GeniusToken1 允许对刷分池进行**封闭式控制**：

> 只有被授权的地址，才能与交易对发生交互。

---

### 在刷分中的优势
- 交易量来源可控
- 数据结构干净
- 避免被第三方污染交易路径

### 适用场景
- 早期刷分测试
- 小规模、高纯度交易量构造
- 对数据质量要求极高的项目

---

## GeniusToken2 —— 貔貅 Token（单向流动型）

### 核心特性
- 允许买入
- 禁止卖出，或对卖出施加极高惩罚
- 实际效果为：**只进不出**

### 设计原因

在大量积分 / 排名系统中：

- 买入行为是正向信号
- 卖出行为往往触发风控或降权

GeniusToken2 用合约逻辑强制构造：

> **稳定、不可逆的买入行为**

---

### 在刷分中的优势
- 可持续产生 Swap 行为
- 几乎不存在卖出痕迹
- 非常接近“真实用户 FOMO 行为模型”

### 适用场景
- 买入权重更高的刷分机制
- 对卖出行为高度敏感的项目
- 激励早期阶段

---

## GeniusToken3 —— Permit2 貔貅 Token（智能合约钱包专用）

### 关键设计前提

> **Genius 使用的钱包地址是智能合约账户，而非普通 EOA。**

这意味着：
- 用户并不是直接用个人地址与 Pair 交互
- 所有交易都由合约中转执行

---

### 问题背景

传统 ERC20 交互流程：


在智能合约钱包中会带来：
- 授权流程复杂
- Gas 成本上升
- 行为路径不自然
- 部分 DEX 兼容性差

---

### 核心特性
- 集成 **Permit2**
- 无需传统 approve
- 保留貔貅（只买）属性

### 设计目的

Permit2 允许：
- 合约直接完成授权与调用
- 交易路径更加简洁
- 行为更接近真实用户

> GeniusToken3 是为 **合约钱包刷分场景量身定制的 Token**。

---

### 在刷分中的优势
- 适配智能合约账户
- 交易路径自然
- Gas 更低
- 不易被识别为异常合约行为

### 适用场景
- 合约钱包体系
- 自动化刷分合约
- 长期、稳定刷量系统

---

## GeniusToken4 —— 收税 Token（行为真实性增强）

### 核心特性
- 买卖均可收税
- 税率可配置
- 税收流向可控（回池 / 回地址）

### 设计原因

**完全 0 成本、0 摩擦的交易行为，在大规模情况下并不真实。**

真实市场一定存在：
- 税损
- 滑点
- 摩擦成本

GeniusToken4 的目标是：

> **让刷分行为在链上“看起来更像真的”。**

---

### 在刷分中的优势
- 交易数据更自然
- 提高对反作弊模型的抗性
- 税收仍然在 Genius 体系内回流

### 适用场景
- 长周期刷分
- 高风控项目
- 强反作弊机制的积分系统

---

## 设计总结

| Token | 定位 | 解决的问题 |
|----|----|----|
| Token1 | 权限控制 | 外部地址干扰 |
| Token2 | 单向买入 | 卖出风控信号 |
| Token3 | 合约适配 | 智能钱包交互异常 |
| Token4 | 行为塑形 | 数据过于“完美” |

---

## 设计哲学

Genius 并不追求：

- 刷得最快
- 量做得最大
- 暴力堆交易次数

Genius 追求的是：

> **在协议规则允许范围内，构造最合理的链上行为。**

这些 Token 不是为了投机，  
而是为了 **工程化地模拟真实市场行为**。
